Levi.css

CSS for the HTML you already write.

Plain HTML in, an application UI out. About 1050 lines of CSS, no JavaScript, no build step.

Native first

Plain ul, table, details. One class on the outer element, nothing on the inside.

One standard

Only the CSS spec. No prefixes, no hacks, no web fonts. If a browser disagrees with the spec, that is the browser's bug.

Quiet by design

Hairlines, soft grays, one accent. Rows are the same height in tables, lists and trees.

    Charts

    The data is the markup. Values are numbers in --value and the browser does the proportions. Colours are tones of the accent, or eight categorical hues with mc-categorical, or yours with --c on a slice, so one thing keeps one colour across charts. A donut slice also needs --from, the sum of the slices before it. Lines are a plain svg. No JavaScript.

    Why another one

    I tried the alternatives first. This is what I did not like.

    AlternativeWhat I did not like
    BootstrapBlocky, chunky and huge.
    shadcn/uiIt needs React.
    Pico, Sugar, Chota, BeerCSS, KelpUIThe right idea, in a design I could not live with.

    Left out on purpose

    If the browser has an element for it, or nearly every application needs it, it is in. Everything else is filler.

    • Grid systems. CSS grid is already there.
    • Carousels. Scroll snap does it.
    • Badges. A status dot is enough.
    • Tooltips. The title attribute and popover exist.

    One file. One link.

    <link rel="stylesheet" href="levi.css">
<body class="mc-theme">
